Security appliances software versions MX 26.2.5 changelog   Executive summary Restored Client VPN connectivity and authentication across affected IKEv1, IKEv2, and Cisco Secure Client configurations. Corrected Auto VPN route installation, preferred-hub forwarding, and iBGP session establishment. Improved routing configuration updates and stability in large OSPF deployments. Corrected VLAN configuration and DHCP forwarding behavior, and restored reliable Bonjour forwarding. Restored Local Status Page access and resolved unexpected reboots following an application recognition service failure. Bug fixes - general fixes Restored RADIUS authentication after changing Client VPN from L2TP to IKEv2. (MX-53935) Corrected Client VPN authentication failures when using a secondary RADIUS server. (MX-53637) Resolved an issue that could unexpectedly disconnect Cisco Secure Client VPN sessions. (MX-56223) Corrected an issue that could prevent an IKEv2 Client VPN connection from a former eBGP peer address after BGP was disabled. (MX-58620) Fixed an issue that could allow additional IKEv2 Client VPN clients to connect but prevent their traffic from passing when another client was already connected. (MX-58243) Resolved an issue that could prevent iBGP sessions over Auto VPN from establishing when intrusion prevention was enabled. (MX-56961) Resolved an issue that could leave Auto VPN tunnels connected but unable to pass traffic after moving a device to another Dashboard network. (MX-58404) Fixed an issue that could leave an IPsec VPN tunnel unable to pass traffic after its peer address or NAT mapping changed during reconnection. (MX-55163) Fixed an issue that could prevent IPsec VPN tunnels from re-establishing after a WAN uplink was disabled and re-enabled on MX HA pairs using virtual IPs and dynamic routing over multiple WAN uplinks. (MX-57483) Fixed an issue that could cause IPsec VPN health checks in passthrough mode to use an incorrect source IP address. (MX-56743) Resolved an issue that could leave routes missing or incorrect after VLAN or IPsec VPN configuration changes. (MX-56049) Corrected an issue that could retain routes excluded by an updated prefix filter. (MX-57706) Fixed an issue in Auto VPN deployments using VRFs that could select a lower-priority hub for IPv4 default-route forwarding even when the preferred hub’s route was available. (MX-57874) Fixed an issue that could leave wired 802.1X clients disconnected after a RADIUS server became reachable again following a reauthentication timeout. (MX-53774) Corrected CPU usage in Summary Reports showing insufficient data after changing between routed and passthrough modes. (MX-58051) Resolved routing disruptions when processing a large OSPF link-state database. (MX-58337) Fixed an issue that could cause active FTP transfers between VLANs to fail when another stateful firewall was in the path. (MX-57059) Reduced CPU overhead when traffic-shaping queues become congested. (MX-56299) Fixed an issue that could disrupt manual Umbrella DNS integration for clients in the default VRF when other VRFs were configured. (MX-55890) When overlapping IPv4 subnets are configured on VLANs in the same VRF, the MX now remains online, retains IPv4 forwarding and DHCP on the lowest-numbered VLAN, and disables them on conflicting higher-numbered VLANs while logging a configuration-validation event. (MX-55897) Fixed an issue that could cause an uplink changed from PPPoE to Direct in Dashboard to revert to PPPoE when the original PPPoE settings were saved on the Local Status Page. (MX-55032) Fixed an issue that could leave group policy firewall rules unenforced at startup when the policy referenced VLANs. (MX-57603) Resolved an issue that could prevent relayed DHCP requests from reaching the MX after a routing change. (MX-48935) Fixed an issue that could interrupt Bonjour forwarding for several minutes after repeated identical queries. (MX-55955) Fixed an issue that could prevent Local Status Page login when the configured password exceeded 30 characters. (CORE-3036) Fixed an issue that could cause an MX appliance to reboot after the application recognition service stopped unexpectedly. (MX-53169) Removed trust in the emSign ECC Root CA - G3 and Comodo AAA Services root certificates from the public certificate bundle. (MX-57964) As part of Cisco's ongoing commitment to proactive security and product quality, the MX engineering team has conducted a comprehensive internal security review. This review resulted in one or more software hardening release(s) that address(e)s multiple internally discovered vulnerabilities. Bug fixes - limited platform fixes Fixed an issue on MX105 appliances that could interrupt Dashboard telemetry and live tools when an unsupported USB modem was connected. (MX-56446) Fixed an issue that could cause C8455-G2-MX secure routers to crash when receiving a large fragmented IPv6 ping addressed to a LAN link-local address. (MX-56970) Corrected PoE operation on the two supported ports of C8355-G2-MX secure routers. (MX-55754) Corrected duplicated per-port PoE power readings and inflated total PoE power usage on C8235-G2-MX secure routers. (MX-54537) Resolved an issue that could cause sustained high CPU usage on C8235-G2-MX, C8355-G2-MX, and C8455-G2-MX secure routers. (MX-57113) Fixed an issue that could prevent SSIDs configured with WEP from broadcasting on MX67W, MX68W, and MX68CW appliances. (MX-56769) Fixed an issue that could cause a link-speed change on one WAN port to affect another on MX75, MX85, MX95, and MX105 appliances. (MX-55138) Resolved an issue that could prevent IPv6 eBGP sessions over IPsec VPN from establishing. (MX-57759) Fixed an issue that could prevent IKEv1 Client VPN clients behind NAT from connecting. (MX-55235) Resolved an issue that could prevent vMX instances running MX 18.2 from upgrading to this release. (MX-57738) Legacy products notice When configured for this version, Z3(C) devices will run MX 19.2.9.1. When configured for this version, MX64(W), MX65(W), MX84, MX100, and vMX100 devices will run MX 18.107.14. Known issues In the new Route Table, BGP routes over IPsec VPN may lack ECMP identification, next-hop addresses, and IPsec peer details. (MX-50932)
